# Afilmory UI/UX 改进研究：保留产品逻辑，重做界面质量

日期：2026-09-11。源码基线：`7b168c2f`。主要体验对象：[lens.misfork.com](https://lens.misfork.com)。状态：方向已获确认，首轮实现与回归完成；详见[实施记录](ui-ux-implementation-2026-09-11.md)。

本文件取代同日上一版“当代摄影画廊”方案。上一版对默认密度、作者卡位置、EXIF 可见性、搜索与地图范围的改动不再作为实施依据；之前展示的交互提案也不再代表建议方向。

## 1. 产品理解

Afilmory 的核心是**以密集照片墙呈现摄影师得意作品，并让访客流畅地浏览、放大观看和探索照片信息**。

首页直接进入摄影内容，多张作品的并置形成视觉吸引力。作者身份融在照片墙里；相机、镜头、时间、地点、影调等信息让访客可以继续探索同一批作品。点开一张照片后，原图、连续切换、缩略图条与 EXIF 共同组成完整体验。作品可以直接以文件名展示，不需要为每张照片编写题目、图注或故事。

这里的“照片优先”体现在直接接触照片、连续看图、可靠画质和自然探索。专业信息与这些目的相互配合。密集布局、嵌入作者卡、常驻技术信息都是当前产品的设计选择，不能仅凭它们不符合某种作品集网站风格，就判断为缺陷。

本轮目标是：**保持这些使用关系，让整个界面更加统一、精确、易读、顺手。** 这是一次完整的界面系统改进，可以重做控件、材质、内部排版、交互状态和响应式细节；产品定位与核心浏览流程作为基线保持。

## 2. 本轮实际检查了什么

### 线上实测

- 桌面首屏：1513 × 778 CSS 像素，5 列密集原比例照片墙；作者卡位于第一列，周围立即可见照片。观察时站点统计为 180 张照片、7 台相机、17 个镜头、23 个城市。
- 搜索与筛选：同一面板承载输入搜索和分类筛选。实际看到长器材名称、筛选项排列、滚动区域、重置与关闭，以及输入框重复焦点轮廓。
- 视图设置：已有最新/最早排序与自动/数字列数设置。因此，不另设“作品/档案”“舒展/紧凑”模式来替代当前操作。
- 桌面查看器：打开 `A7C04296`，实际查看大图、上一/下一张、缩放、底部缩略图条和常驻 EXIF。拍摄参数、影调分析与设备信息都属于现有界面。
- 移动宽度：在 390 × 844 的浏览器模拟视口查看首页、滚动照片墙、打开 `A7C03333` 及其底部照片信息面板。滚动约 778px 后，日期条仍显示，视口内没有搜索、地图或视图按钮。
- 地图：实际进入 `/explore`，看到区域/照片模式、国家标记、返回、缩放及信息卡。观察时显示 106 张 GPS 照片、6 个国家。本次底图未正常显示，仅标记和控件可见，因此不对底图配色或完整地图使用质量作结论，也未将原因归咎于应用代码。

移动检查属于浏览器模拟，不代替 iOS Safari、Android 或软键盘真机验收。以上统计仅记录当时观察，不是产品固定值。没有运行访客研究或测量改版效果。

### 源码交叉核实

复核作者卡、照片墙、操作组、搜索面板、筛选按钮、查看器/EXIF、地图与共享材质样式。使用最新 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 检查焦点、长文本、触摸目标及状态表达。规范用于检查实现质量，不用于重新决定产品受众。

## 3. 设计基线

| 维度     | 保持的产品关系                                                 | 本轮可以改进的界面内容                                   |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| 首页     | 原比例、高密度照片墙；作者卡嵌入桌面网格，手机沿用现有首部结构 | 卡内对齐、间距、按钮、统计、照片悬停层；不同列宽的排版   |
| 浏览密度 | 现有自动/数字列数和排序                                        | 控件清晰度、当前值反馈、尺寸细调，首屏照片密度不明显下降 |
| 查看器   | 原图、连续浏览、缩略图条、桌面常驻 EXIF、手机信息面板          | 控件一致性、数据阅读、背景材质、选中/焦点反馈、安全区    |
| 搜索筛选 | 统一面板和现有条件规则、搜索范围与查看器集合                   | 分组、类型区分、长文本、已选反馈、取消与空结果恢复       |
| 地图     | 地理探索、区域/照片模式及现有范围、聚合和返回逻辑              | 标记状态、控件、浮层、数量与动作的表达                   |
| 视觉身份 | 暗色、现代无衬线、适度通透材质、照片取色                       | 明确表面层级，校准透明度、阴影、强调色及文字对比         |

保持逻辑不等于冻结所有像素。内边距、图标、字级、局部排列、手机作者卡高度和面板尺寸都可以重新设计，只需证明它们改善原有使用方式。默认 4px 照片间距作为比较基线，不预设大幅扩张留白或减少列数。

## 4. 改进重点

### A. 统一界面材质，建立同一个产品的视觉语言

**观察与源码：** 作者卡偏蓝黑实色，搜索面板使用大块玻璃材质，查看器的背景取色与底部缩略图条更明亮，地图和通用弹层又各有配方。多处重复叠加渐变、阴影和光晕。它们各自能用，但整体不够统一。

**改进：** 给普通面板、浮层、照片上的控件分别定义固定配方，统一同类组件的底色、边框、模糊和阴影。保留照片取色的氛围，校准其亮度和饱和度上限，让明亮照片背景下的缩略图边框、文字和按钮依然清楚。大小不同的 Tooltip、菜单与模态框应有对应的视觉重量。

**落点：** `MasonryHeaderMasonryItem.tsx:200`、`ExifPanel.tsx:72`、`packages/ui/src/dialog/dialog.tsx:97`、`packages/ui/src/tooltip/index.tsx:36`、`tailwind.css:166`。

### B. 作者卡在原位置内重新排版

**观察：** 当前卡片包含头像、名称、社交、三个主操作和统计。桌面作为照片墙中的一个单元很有辨识度；手机上同一套垂直间距让卡片约占 340px 高，接近模拟视口的四成。

**改进：** 保留卡片全部职责和入口，用一套明确间距关系组织身份、操作、统计。手机可在卡片内部压缩头像/名称之间的空隙，调整社交与身份的排列，把空间还给首批照片。桌面按实际列宽处理长站名、统计和筛选摘要。主要操作、次要社交与统计建立清楚的视觉层级，补齐图标的光学尺寸和可发现性。

**验收：** 同一内容库下，手机首屏能看见更多照片，三个主操作仍容易点按；桌面作者卡仍自然嵌在照片墙里。准确高度通过同屏对照决定，不先设一个宣传页式头部。

**落点：** `MasonryHeaderMasonryItem.tsx:197`、`:231`、`:286`；`ActionGroup.tsx:45`。

### C. 密集照片墙更精确，而不是更稀疏

保留比例、默认密度、排序与已有参数预览。改进缩略图边界、hover 遮罩、文字内边距、文件信息与曝光参数的行距，统一 HDR/Live 等标识位置。分别检查暗图、亮图和高饱和图片，避免所有照片套同一个过重遮罩。

键盘聚焦应得到与悬停相称的可读反馈。现有放大反馈可校准幅度与速度，不把取消所有动效当成先验答案。不能通过永久图下注释或降低默认列数制造所谓观看节奏。

**落点：** `MasonryPhotoItem.tsx:205`、`:285`；`MasonryRoot.tsx:268`。

### D. 搜索筛选：提高信息密度的质量

**已确认的实现问题：** 输入框外层 `focus-within` 圆角 ring 与全局 `input:focus-visible` 的矩形 outline 同时出现。需要由复合控件统一承接焦点边界，避免两个轮廓互相打架，并继续保留明确的键盘焦点。

**真实内容暴露的问题：** 长相机/镜头名称占据大量横向空间。当前按钮以 12px 字号、44px 最小高度、单行省略呈现，完整名称依赖 `title`；手机不能把悬停提示当作可靠的完整阅读入口。

**改进：** 保留统一面板，在现有分组内调整项目排列、文字对齐、长名称换行/展开方式和选中标记。搜索命令与照片结果用清楚的类型与行结构区分。已选条件可以直接取消；零匹配在原结果位置给出清除条件的动作。范围与计数文案准确描述当前能力。

相机、镜头 `displayName` 同时用于筛选 ID；显示优化不能悄悄清洗名称、合并项目或改变筛选值。面板显示的 106 个筛选项包含标签、设备和地理条件，不能解释为 106 个器材选项。计数与可见分类的对应也应复核。

**落点：** `CommandPalette.tsx:407`、`:427`、`:454`；`tailwind.css:116`；`FilterPanel.tsx:51`、`:64`；`filter-options.ts:54`。

### E. 保留查看器的专业感，改善阅读与连续操作

桌面 EXIF 和缩略图条继续默认显示。照片信息可以保持丰富，通过数据行对齐、标签与数值字重、数字宽度、长值换行、分组间距和分隔，让内容更易扫描。统一常用参数的小块样式与 Raw EXIF 的数据阅读规则。

查看器的关闭/分享、两侧切图、缩放和缩略图选中态采用一致的控件与反馈。选中的缩略图需要在各种取色背景下清楚可辨；多个关闭入口通过所属面板和辅助名称明确作用。手机信息层保持现有结构，打磨展开、内部滚动、关闭、安全区和横屏表现。

本轮不把标题/故事改成信息主线，也不以默认折叠 EXIF、缩略图取得简洁。已有可选描述可在当前信息区域自然处理，不要求作者补写文案。

**落点：** `PhotoViewer.tsx:325`、`:349`；`PhotoViewerToolbar.tsx:39`；`ExifPanel.tsx:54`、`:87`；`ExifRow.tsx:10`；`exif/ExifFieldRow.tsx:7`。

### F. 手机长滚动：让已有操作仍然可触达

**线上已复现：** 在 390 × 844 模拟视口滚动约 778px 后，作者卡和搜索/地图/视图操作全部离开视口，只保留日期条。

**改进：** 沿用现有三项动作，在长滚动中提供紧凑、不会遮住关键内容的入口。具体位置需要和日期条、安全区、手指操作一起校准，可以在回滑时显露同一操作组。保持原作者卡和操作目的，不新增页面分类或底部多标签导航体系。

**落点：** `MasonryRoot.tsx:245`；`ActionGroup.tsx:36`；`components/ui/date-range-indicator/DateRangeIndicator.tsx:98`。

### G. 地图和边界状态纳入同一套界面

地图继续服务于照片位置探索。统一返回、模式切换、缩放、标记和信息卡的尺寸与状态；数量说明与可点击动作清楚区分。聚合预览的更多数量若表现为操作，就复用已有整组照片查看能力兑现该动作。保持当前地图范围和返回关系。

加载、零匹配、原图失败、地图失败、Raw EXIF 等状态统一图形、字级和动作布局。保留已经分类的真实错误与重试，不让视觉动效掩盖失败。

地图底图本次没有正常呈现，应在可用网络与目标设备上单独复核后再评价；不把未看到地图当作新设计的依据。

**落点：** `ClusterPhotoGrid.tsx:148`；`MapInfoPanel.tsx:190`；`MapLoadingState.tsx:8`；`RawExifViewer.tsx:306`。

## 5. 全局规则

- 继续使用现有本地 Geist 与 CJK 回退。为标题、正文、标签、辅助文字、技术数值定义少量明确角色，优先提高对齐与分组质量。
- 高频动作统一图标的线重、光学居中、视觉尺寸和容器；专业摄影符号保留。无需为统一外观更换整个图标依赖。
- 普通、悬停、按下、选中、聚焦、禁用、加载有一致表达。选中不能只依赖颜色，焦点不能重复绘制。
- 已有 `accent-content` 可读前景色机制需要被所有强调色实底组件实际使用。`FilterPanel.tsx:64` 等固定白字属于应修正的适配风险；未测量的组合不直接宣称全部不达标。
- 保留舒适的触摸热区，分别管理可见图标与点击区域。细调圆角和间距时覆盖长中文、英文、器材名及不同列宽。
- 动效说明打开、切换、返回与选择，保持可中断和减少动态效果支持。只在测量后声称性能改善。

## 6. 新的实施顺序

### 第一批：同一页面、同一内容的界面样板

选取当前作者卡、搜索/筛选面板、完整桌面查看器及手机对应界面，做同位置的前后对照。照片、顺序、列数、功能入口和信息范围作为对照基线。

这一批包含材质配方、字号/间距、图标/按钮、筛选长文本、输入焦点和 EXIF 数据行。手机作者卡内部排版可以一起精修。新方案必须一眼仍能认出是现在的 Afilmory。

### 第二批：把同一规则覆盖到全部界面

迁移视图设置、地图控件/浮层、分享、Raw EXIF、Tooltip、Toast 和加载/错误等表面。沿用当前组件职责和交互，避免产生第四套按钮或临时样式。

### 第三批：打磨完整使用过程

完成手机长滚动操作可达性、筛选取消与空结果恢复、长文本和软键盘、安全区、焦点/返回与动画边界。使用相同照片库验收浏览、看图、筛选、地图、分享的完整流程。

本轮不加入系列策展、作者叙事、时间归档、新搜索结果页、地图范围切换、默认沉浸模式或新导航分类。这些能力若未来需要，另按具体使用问题评估。

## 7. 验收与工程边界

设计验收关注可观察的变化：同屏照片数量与面积没有因装饰明显退化；原有动作容易找到；信息丰富但更易读；不同页面像同一个产品；滚动、切换与返回稳定。

实施时继续保护：

- 虚拟瀑布流、原比例和列宽测量。作者卡内部高度发生变化，也要正确触发测量和位置恢复。
- 查看器几何、WebGL/DOM 渲染、缩放和转场；背景/按钮样式调整不应干扰媒体资源生命周期。
- 现有 URL、筛选、搜索和地图集合语义；返回原位置、焦点、地图相机状态。
- 按需分片、首屏优先加载、取消、缓存与 Blob 所有权、真实重试。
- Radix 焦点/模态隔离、Escape 层级、触摸安全区、减少动态效果。

使用 320/390/768/1024/1440 等宽度，以及空图库、一张、少量、大图库、不同横竖比例、缺少 EXIF/GPS、长文本进行验证。浏览器模拟之外补真机测试。性能用相同条件比较，不用“少了几个阴影”推导加载或帧率提升。

本报告描述设计基线与改进范围。首轮完成内容及验证结果见[实施记录](ui-ux-implementation-2026-09-11.md)。
