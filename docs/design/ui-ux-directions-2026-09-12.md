# Afilmory UI/UX：三个待选主方向

日期：2026-09-12。状态：**方向分析记录；A/C 与修订后的 B 已实施**。本文是基于现有界面、源码和浏览器观察的设计分析，不是用户研究，也不表示原始提案所有条目都已获准开发。本次记录的本地基线为 `525d0f0e`，开始分析时工作区干净。

后续决策：用户选择先实施复核后的 A 和 C，B 留待之后讨论。实际改动与验收见 [A/C 实施记录](ui-ux-ac-implementation-2026-09-12.md)。原提案保留供追溯，不代表所有条目都需要新增开发。

2026-09-13 修订：用户认为并排侧栏削弱沉浸感，否决该方向，并确认保留现有模态的交互稿。实际 B 只改进面板内部的计数、结果分组、完整构图预览和会话恢复，继续使用整墙模糊与即时筛选。详见 [B 实施记录](ui-ux-b-implementation-2026-09-13.md)；下文关于非模态侧栏、照片墙重排和手机两档面板的原始建议不作为实施范围。

三个方向服务于同一个摄影作品展示产品、同一批访客，分别强调连续观看、边看边找、看图与参数对照。它们不划分新的受众，不增加博客、策展、推荐或资产管理功能。选定主方向后，再考虑吸收其他方向的细节。

## 复核修正：真正相对当前实现的差异

用户指出上一轮说明把现有能力混入了改造亮点。复核后确认：即时筛选、照片结果缩略图、照片结果类型标签、已选条件标签、作者卡匹配照片数、连续切图、缩略图条、桌面默认 EXIF、拍摄参数卡片和返回定位均已存在。这些不计为本轮新增。原文“稳定操作”“参数与单位位置稳定”等目标也不足以单独构成重构项目。原图加载、错误、重试和缩放倍率也已位于媒体区域，撤回将“状态靠近照片”列为新增的表述。

| 归属 | 当前实现                                                         | 待选的具体修改                                                                       |
| ---- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| A    | 查看器有当前集合和索引，工具栏未显示来源及序号                   | 显示实际查看集合的来源和当前序号/总数。A 应降为局部增强，不能视作同等规模的全面改造  |
| B    | 搜索筛选是带全屏模糊遮罩和模态隔离的底部面板                     | 桌面改为可收起的非模态侧栏，照片墙与侧栏可同时操作                                   |

| B    | 照片已有 40px 方形裁切缩略图和类型标签，与命令共用同一列表       | 照片与筛选命令分组；照片预览扩大并保留构图比例。增量是分组和预览规格，不是新增缩略图 |

| C    | 文件属性在前，拍摄参数已有两列卡片，器材在更后面                 | 前移现有拍摄参数与器材，文件属性后移；不重做已有参数能力                             |

因此，A、B、C 不是三个同等完整的重构方案。真实改造范围主要是 B 的搜索筛选空间关系、C 的手机照片与信息布局，A 仅是序列上下文表达的补充。下文为原方向分析，应以上述差异和范围修正为准，不能把保留项算作交付增量。

## 共同基础与已知事实

此前的[设计评审](ui-ux-review-2026-09-11.md)和[首轮实施记录](ui-ux-implementation-2026-09-11.md)已经确认：密集原比例照片墙、桌面内嵌作者卡、默认 4px 间距、自动/数字列数、统一搜索筛选、连续查看器和地图构成产品基础。共享材质、焦点、手机浮动操作、筛选取消与空结果恢复已经具备，不应再把它们包装成新方案的新增能力。

三个方向均保留这些基础，保留桌面默认 320px EXIF 侧栏和 filmstrip，不通过隐藏专业信息或大幅减少照片密度制造简洁，也不要求作者为文件名照片补写标题与故事。

| 本轮观察                                                                                   | 可以据此判断什么                                                                                                                  |
| ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 线上照片库为 180 张，本地为 172 张，内容与配置不同                                         | 可以讨论各自的使用问题，不能据此量化改版前后的照片面积或效果。                                                                    |
| 本地稳定桌面视口 1375 × 707，搜索面板为 768 × 608，约占屏高 86%，背景照片墙模糊            | 搜索时照片墙难以同时用于判断筛选结果。                                                                                            |
| 在该本地库选择 SONY 条件后，作者卡显示匹配 109 张；面板反馈主要是 1 项已启用、106 个筛选项 | 照片匹配数与可选条件数分处不同位置。106 是筛选项数量，不能解释成照片或器材数量。109 只属于这次内容库和选择。                      |
| 手机信息面板最大高度为 `60vh`，源码与浏览器均核实                                          | 信息层会占用明显的观看空间。模拟器继承了 110% 缩放，配置视口与稳定后的 CSS 视口不同；这里只记录高度约束，不提供真机精确像素尺寸。 |
| 本地预览访问远程原图出现连接失败                                                           | 可以检查失败反馈，不能把该网络现象视作产品设计本身的问题，也不能据此判断正常原图的画质或加载体验。                                |

判断依据包括状态反馈、用户控制、识别而非记忆等 [Nielsen Norman Group 启发式原则](https://www.nngroup.com/articles/ten-usability-heuristics/)。这里据此推导的是“让动作与结果更容易同时理解”，并非规范规定必须采用某种侧栏。焦点、长文本、触摸替代操作、安全区和减少动态效果继续依据 [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)检查；这些规则不替代产品定位。

## A：连续观片

### 主导体验与整体视觉

让照片墙、单张观看、连续切换和返回组成一条清楚的浏览过程。视觉重心放在图像之间的连续关系：照片边界准确，操作位置稳定，当前照片与序列状态明确；材质继续使用现有暗色磨砂体系。作者卡保持嵌入位置，身份、三项操作与统计的层级清晰，不扩大成独立宣传头部。

### 各界面的具体变化

**桌面照片墙与搜索：** 保留密度和原顺序，围绕当前照片统一悬停、键盘聚焦与打开反馈。搜索继续是现有统一入口，重点整理输入、照片结果、筛选命令的阅读层级；本方向不优先改变大面板的空间形态。

**查看器：** 补充准确的序列来源和序号，例如来自当前筛选或地图的一组照片，以及“第几张/共几张”。数据来自实际查看器集合，不把文本搜索返回的少量结果误写成切图范围。导航、缩放和分享分区：上一张/下一张与序列信息相邻，缩放反馈靠近媒体，分享与关闭保持稳定位置。EXIF 与 filmstrip 默认保留；快速切图时不让外围控件重新排队。

**手机与地图：** 将常用查看器操作组织在稳定区域，协调 filmstrip、信息入口和安全区，避免同一动作在切图后换位置。保留已有浮动三操作。地图进入查看器时标明当前照片组；关闭后回到原地图位置，照片墙往返同样保留定位与焦点。

### 前后用户路径

当前：从一张缩略图进入查看器，切换数张后依靠图片或记忆判断自己在什么集合中，关闭返回照片墙。

拟议：进入时看到来源与序号；通过相邻导航和 filmstrip 连续看图；查看器集合不变；关闭回到原来浏览的照片附近。改进目标是定位关系更清楚，不声称已提高浏览时长。

### 取舍、边界与优先级

优先处理序列信息和操作分区，再校准手机布局，最后统一跨地图返回的表达。主要落点为 [PhotoViewer](../../apps/web/src/components/ui/photo-viewer/PhotoViewer.tsx)及其工具栏、filmstrip；集合解析继续复用 [usePhotoViewer](../../apps/web/src/hooks/usePhotoViewer.ts)。不改导航集合规则、排序、原图生命周期或缩放算法，不增加新的“沉浸模式”。风险是把安静误做成隐藏动作，或让序号成为又一层照片遮挡。

**验收情境：** 全库、筛选集合、地图聚合和直接分享链接分别进入查看器；快速连续切图、首尾照片、键盘与触摸返回；检查来源/总数准确、焦点回到可见照片、默认信息仍在。关闭分享或 Raw EXIF 只退出当前层。

## B：并行探索（推荐）

### 主导体验与整体视觉

让访客选条件时仍然看见同一面照片墙及变化。桌面由“面板覆盖观看区域”变成“照片与工具并列”：墙占主要空间，搜索筛选位于可收起侧栏，边界清楚，避免整墙模糊。侧栏关闭后恢复原有完整照片墙和内嵌作者卡，不留下永久导航栏。

### 各界面的具体变化

**桌面照片墙与搜索：** 从现有统一入口展开侧栏，墙与侧栏都可操作。条件立即应用，在条件附近显示当前照片墙的匹配数；照片墙同时呈现结果，零匹配仍可原地恢复。侧栏内部将“照片”和“筛选命令”分组，清楚说明查询命中、启用条件与照片匹配数各自的含义。

必须保留 [CommandPalette](../../apps/web/src/modules/gallery/command-palette/CommandPalette.tsx)现有查询范围：文本照片检索来自全库索引，不能借改版悄悄变成只搜当前筛选。文本输入本身也不能被新增为照片墙过滤条件。照片组与命令组只改变呈现；保留原筛选 ID、组合语义、照片排序和搜索打开照片时的查看器集合，不把文本命中列表直接用作新 filmstrip。

**查看器与地图：** 从侧栏或墙打开照片，沿用已有查看器关系；关闭后恢复同一批筛选结果及侧栏状态。地图仍使用原范围和区域/照片模式，不增加“只看当前屏幕”之类范围开关。进入地图再返回时，已应用条件与工具开合状态清楚可恢复。

**手机：** 使用分段高度面板，低位支持选择条件和观察部分照片，高位容纳查询、长列表与软键盘。所有条件仍立即应用。“查看 N 张”仅收起面板，N 来自当前照片墙，不引入草稿条件或第二个提交步骤；关闭也不撤销已应用条件。伸展、收起与关闭均提供按钮，不能只靠拖动。每种高度下都明确照片墙是否可操作，避免可见但被透明遮罩拦截的假象。

### 前后用户路径

当前：打开大面板，选 SONY，看到已启用条件与筛选项计数；关闭后才容易检查照片墙及匹配 109 张的反馈；需要调整时再打开。

拟议：打开侧栏，选同一条件，原处显示匹配 109 张，旁边的墙同步更新；继续选或取消镜头条件，直接观察结果；点照片观看，返回继续筛选；完成后收起侧栏。手机走相同立即应用路径，“查看 N 张”负责把空间还给照片。

### 取舍、边界与优先级

这是改变面板与内容关系的方案，不是把原模态框简单移动到右侧。桌面必须调整模态隔离和焦点管理，不能保留背景 `inert` 或把键盘锁在侧栏；同时保持弹出查看器后的模态规则。

优先完成侧栏、就地照片数与立即反馈，再做结果分组和手机分段面板。复用现有筛选派生结果；不新增索引服务或待提交状态。侧栏占宽会触发瀑布流重排，需由 [MasonryRoot](../../apps/web/src/modules/gallery/MasonryRoot.tsx)的实际容器测量承接。保留自动/数字列数设置，开合按照片身份与相对位置处理定位，不能只恢复一个已经失效的滚动像素值。窄桌面需验证最小可用照片宽度，不能硬塞工具使照片退成细条。

**验收情境：** 桌面持续选、取消多个条件，不关闭工具也能判断结果；文本搜索命中当前筛选外的照片时，行为与基线一致；零结果、一张、大图库、长器材名、侧栏开合与浏览器后退；手机软键盘和两档高度下，当前条件、匹配数和收起动作均可达。

## C：摄影观片台

### 主导体验与整体视觉

把“看照片”和“读摄影信息”的空间关系组织得更精确。照片仍主导页面，信息靠固定对齐、参数顺序和稳定分区获得专业感，不靠增加仪表盘或技术装饰。照片墙保持原密度，作者卡继续属于墙的一部分。

### 各界面的具体变化

**桌面照片墙与搜索：** 照片参数预览使用稳定的单位与信息角色；统一搜索的照片结果与器材条件更易区分，但不改变查询规则或优先引入并行侧栏。地图维持既有探索入口。

**查看器：** 依据 [ExifPanelSections](../../apps/web/src/components/ui/photo-viewer/ExifPanelSections.tsx)现有数据，将拍摄参数和器材放在前面，文件格式、体积、像素等放在后面。完整信息保留默认可见且可滚动，不用折叠组隐藏内容。桌面 320px EXIF 侧栏与 filmstrip 不藏。原图加载、原图失败/重试、缩放比例及适应画面的反馈靠近媒体，明确正在看的是哪种状态，不能把缩略图成功当作原图成功。

**手机：** 打开信息后，从底部覆盖大图改为上下分区：完整照片在一块独立区域内适应显示，信息在另一块区域内滚动，filmstrip 保留，彼此不遮盖。分区高度可调整，并提供“更多照片空间/更多信息空间”等按钮替代拖拽。完整显示不等于等大显示：信息占高时照片会缩小，需要真实内容对照后确定舒适范围。

**地图衔接：** EXIF 里的位置与小地图继续连接到现有地图；返回后保持当前照片与信息阅读位置，不将地图变成新的地理分析工具。

### 前后用户路径

当前：打开照片，先经过文件属性再读拍摄参数；手机展开信息覆盖部分媒体，读完再关层继续看图。

拟议：打开即看到优先参数，向下仍能读到全部文件数据；手机同时看到完整构图和参数，按需调整空间；切到下一张时参数位置稳定，可继续阅读。已有原图连接错误仍明确显示错误，不以新布局掩盖。

### 取舍、边界与优先级

先完成 EXIF 顺序与媒体状态归位，再实现手机分区。这个方向对媒体几何影响最大：需要保护 WebGL/DOM 渲染、缩放边界、入场/退出转场、面板尺寸变化和 filmstrip 预留高度。不能仅把图片 CSS 高度压小而不通知既有测量链路。数据来自静态 manifest 和已有解析，不新增编辑、评分、并排比片或批量管理功能。

**验收情境：** 横图、竖图、全景、缺少 EXIF/GPS；桌面全部信息可读，手机分区调整后照片不裁切、参数不被安全区遮住；缩放后开关信息、旋转屏幕、原图失败后重试、快速切图，检查几何、序号和媒体状态一致。

## 比较与选择建议

| 维度             | A 连续观片                     | B 并行探索                       | C 摄影观片台                      |
| ---------------- | ------------------------------ | -------------------------------- | --------------------------------- |
| 首要改善         | 看图、切图、返回的连贯性       | 选条件与看到照片结果的反馈       | 完整照片与摄影信息的对照          |
| 最明显的桌面变化 | 序列信息与操作分区             | 可收起搜索筛选侧栏，墙仍可见     | EXIF 顺序与媒体状态布局           |
| 最明显的手机变化 | 稳定操作区                     | 分段面板与“查看 N 张”收起        | 完整照片、filmstrip、信息上下分区 |
| 主要工程风险     | 来源表达与导航状态一致         | 非模态焦点、容器重排、定位恢复   | 媒体几何、缩放、转场与高度调整    |
| 核心验证问题     | 我知道在看哪组、从哪里返回吗？ | 我能边选边看到同一图库的结果吗？ | 我能同时看完整构图并读参数吗？    |

**建议本轮选择 B。** 现有功能与数据已经能筛出照片，但大模态隔开了操作和图像反馈。并行探索最直接改善“在同一图库发现照片”的过程；无需新内容、推荐算法或额外管理能力，收起后依然是原照片墙。建议依据是当前可观察的交互关系，不是已经测得的效率提升。
