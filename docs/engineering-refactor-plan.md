# 软件工程改进实施计划

本计划落实 [工程审计](./art-quality-review-2026-09-08.md) 中认可的方向。依次推进，保持现有 UI、功能、静态部署方式和官方插件行为；每阶段通过针对性验证后进入下一阶段。

## 实施顺序

| 阶段 | 工作                                                              | 验收标准                                                     | 状态   |
| ---- | ----------------------------------------------------------------- | ------------------------------------------------------------ | ------ |
| 1    | 分离 logger 工厂；源模块循环与边界检查；Web 单测类型检查          | 违规 fixture 被拦截，合法类型依赖放行，测试调用符合真实 API  | 已完成 |
| 2    | 媒体事件、阶段错误和转换结果；i18n 留在表现层；修复 TIFF 像素解释 | 无转换和失败可区分，保留 cause，灰度与透明像素正确           | 已完成 |
| 3    | 共享转换订阅、队列取消、runtime 资源归属；下载超时；DOM 解码失败  | 独立消费者不互相取消，过期结果不交付，dispose 清理待办与缓存 | 已完成 |
| 4    | Builder 用户请求、只读计划和执行上下文分离；收窄阶段依赖          | 规划不修改用户选项，执行输入显式，增量构建及插件事务保持     | 已完成 |
| 5    | PhotoRepository 只读快照与结构共享                                | 旧快照稳定，变更实体换身份，非法分片不部分提交               | 已完成 |
| 6    | TypeScript Worker 入口与双向消息协议                              | 普通模块共享逻辑，编译检查双方消息，保留取消与 bitmap 所有权 | 已完成 |
| 7    | 工程文档与规则清理；完整类型、lint、格式、单元及生产回归          | 检查通过，记录环境限制和未覆盖范围                           | 已完成 |

## 各阶段共同要求

- 优先沿现有模块边界收敛接口，不引入框架或按文件长度拆分。
- 先明确可观察契约，再补能发现真实失效的测试；复用已有事务和生命周期测试。
- 保持 manifest v2 / Web delivery v3、资源 lease、导航单一来源、Builder 插件事件顺序和原子提交。
- 只在外部边界使用替身；关键异步顺序、真实编码样本和生产 Worker 绘制分别验证。
- 本机 pnpm 启动异常时使用仓库已安装工具直接入口，记录真实执行命令；生产测试使用隔离 fixture，不访问照片源。

## 完成记录

实施过程中在此记录每阶段的改动、验证结果和必要的兼容决策。

### 阶段 1

- logger 工厂不再依赖执行上下文，静态运行时循环消除。
- contracts 解析各包 TypeScript 路径，检查循环、生产到测试、表现层反向依赖和公开包入口；含 5 组正反例。
- Web 单测纳入独立 tsconfig，修复 21 处遗漏的 fixture、mock 和 ref 类型问题。
- 验证：149 个测试文件、998 个用例通过；Web 单测及工具类型检查通过，改动相关 lint 通过。

### 阶段 2–3

- 转换结果区分原图原因与成功产物，错误保留 stage / code / cause；核心事件通过表现适配层翻译。
- 删除 HEIC 模块级 Blob 缓存。TIFF 灰度/alpha 按 decoder 通道布局解释，透明图输出 PNG；不支持的布局显式失败。
- 共享任务独立订阅；最后取消移除排队任务；活动解码保持并发额度直到结束；runtime.dispose 可等待解码退出。
- XHR 60 秒无字节进展超时，结算后解除事件和计时器；原生回退不把失败转换写入缓存。
- 查看器使用内容状态联合，DOM/WebGL 回退后的解码失败统一报告一次，lease 清理幂等。
- 验证：95 个 Web 测试文件、562 个用例及 Web 单测类型检查通过；包含真实 TIFF 解码、共享取消、迟到结果、runtime disposal 和 DOM error 测试。

### 阶段 4

- BuildSession 保存冻结的 BuildRequest，生命周期载荷独立使用 BuilderPluginOptions；旧插件失效提示在规划时显式捕获。
- DiffPlanner 返回包含任务、原因及处理策略的 BuildPlan，不修改 session.options；同体积任务按 key 稳定排序。
- worker/cluster 使用相同的显式 processorOptions，cluster IPC 不再从用户参数推导执行中间态。
- 配置由 services.config 提供唯一来源；各阶段按使用能力接收上下文，存储契约不再暴露具体 manager 类。
- 验证：46 个 Builder 测试文件、410 个用例及 Builder 类型检查通过；增加冻结输入、独立失效提示、可复现计划和双执行模式策略一致性测试。

### 阶段 5

- Repository 拥有与输入隔离的深冻结快照，查询返回递归只读对象和数组；Builder 继续使用可变磁盘 DTO。
- 分片先完整校验和构造候选数据，再原子发布；变更实体更换身份，未变节点结构共享。
- 通用 abortable helper 保证忽略 AbortSignal 的 transport 也能及时结算，迟到结果不发布。
- 验证：Web/schema 99 个测试文件、598 个用例通过；新增 6 个快照/原子性/并发/取消用例通过，Web 单测类型检查通过。

### 阶段 6

- 使用标准 TypeScript 模块 Worker，删除 raw JS、函数序列化和手动常量注入；共享请求/响应协议与尺寸、LOD/grid 实现。
- Worker 以独立 WebWorker 环境编译；保留 session 和 transfer 所有权，补充重复 session、迟到 base/tile、transfer 失败和 HTTP 错误回归。
- 保留 terminate 后在途 bitmap 的接收释放，避免提前解除消息回调造成泄漏。
- 验证：17 个测试文件、112 个用例及主包/Worker 类型检查通过。生产浏览器确认真实 Worker 资产加载并绘制 canvas。

### 阶段 7

- 新增 [工程契约](./engineering-contracts.md)，同步媒体生命周期、测试指南、AGENTS、README 和 Changelog；清除过时 SSR/backend 目录规则及 Electron 导航提示。
- 完整回归发现 React Compiler 按 Repository 身份缓存 getPhotos；改为直接订阅快照，并移除过滤缓存的冗余版本号。生产用例故意延迟详情分片，验证已显示摘要的查看器能收到新快照。
- 保持 beforeProcessTasks 插件修改任务的行为；实际执行列表参与后续对账和事件，执行副本中的日期不与计划共享。
- 冷启动浏览器回归发现 Vite 延迟发现地图依赖会整页重载；显式预构建相关依赖后，冷启动桌面/触摸回归通过。
- 调整无类型信息的 ESLint undefined 参数规则，避免自动修复删除 TypeScript 必需参数；保留其余规则及全部覆盖率门槛。
