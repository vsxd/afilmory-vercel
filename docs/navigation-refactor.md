# 导航重构方案与验收约定

## 问题与范围

现有实现把 Router、图库筛选 atom、查看器开关/索引 atom 分别作为状态源，再用 effect 双向同步。跨模块跳转因此需要同时协调 URL、列表和查看器；关闭后的 500ms 定时器还有机会覆盖新导航。生产构建复现了尾斜杠详情打不开、地图往返丢失排序、地图参数污染图库、返回图库重新打开详情四个问题。

本次重构覆盖图库、照片详情、地图、命令面板以及分享入口。不改图片加载、Builder 和 WebGL engine。保留现有公开路径，不把页面结构迁移与导航语义变更混在一起。

## 状态归属

- Router 是页面、当前照片和图库筛选的唯一来源。照片 ID 从路径读取，索引由当前列表推导；不再用 effect 把索引回写 URL。
- NavigationController 属于 AppRuntime，直接读取 Router 已提交的 snapshot，提供业务命令。组件不需要复制 location/navigate 到 atom。
- 来源上下文保存在带版本号的 history state 中，包括来源地址、来源历史 key、照片序列、图库筛选和地图视角。DOM 元素不写入 history state。
- 图片关闭动画只保留当前 location key 对应的呈现状态。动画完成后提交关闭；期间若发生别的导航，旧关闭请求失效。
- 列数等设备显示偏好仍留在 Jotai/localStorage，与可分享的 URL 筛选分离。
- 图库滚动位置、地图视角属于运行时恢复缓存，有容量限制；浏览器刷新后的详情通过 URL 和可用 history state 恢复，缺失来源时使用明确的安全返回地址。

## 导航行为

| 用户操作                 | 历史行为                  | 上下文与返回规则                                           |
| ------------------------ | ------------------------- | ---------------------------------------------------------- |
| 图库打开照片             | push                      | 保存当前筛选和列表顺序                                     |
| 地图打开照片             | push                      | 保存地图地址与视角；聚合组使用组内照片序列                 |
| 详情上一张/下一张        | replace                   | 保留最初来源，不向历史栈堆叠每张照片                       |
| 关闭详情                 | 验证后 back，否则 replace | 只有确认前一条记录就是来源才后退；直接访问和刷新走安全回退 |
| 图库或详情查看地图       | push                      | 保留图库筛选；地图“返回图库”始终进入图库                   |
| 地图返回图库             | replace                   | 仅恢复图库筛选，不携带 mode/photoId/locationId 等地图参数  |
| 修改图库筛选或排序       | push                      | URL 更新直接驱动列表，浏览器后退可以撤销筛选               |
| 命令面板在地图上应用筛选 | push 图库                 | 用户立即看到筛选后的图库，不隐式修改后台状态               |
| 地图切模式、选点         | replace                   | 保留来源上下文，避免每次地图交互增加历史记录               |
| 分享照片                 | 不导航                    | 生成稳定详情 URL，不包含私人浏览来源和地图参数             |

原生锚点保留复制链接、修饰键点击和新标签页语义。普通点击通过统一导航命令携带应用内上下文。历史 returnTo 链接仍支持安全的站内回退，但新链接不继续嵌套 returnTo。

## 路由与查询契约

`/` 管理图库筛选，`/photos/:photoId` 复用图库筛选，`/explore` 管理地图查询。详情与地图均接受尾斜杠。照片 ID 统一编码/解码；非法编码和未知照片进入安全失败路径。跨模块只传递各模块允许的查询参数，拒绝站外、协议相对地址和不受支持的返回路径。

## 实施顺序

1. 建立纯路由解析/查询清洗函数与可独立测试的导航控制器。
2. 迁移图库、详情和筛选状态；删除旧双向同步与 Router 镜像。
3. 统一地图、命令面板和分享入口；接入动画完成与位置恢复。
4. 将旧原子驱动测试迁移为真实 Memory Router 行为测试，补齐生产构建端到端导航回归。
5. 执行类型、lint、单元测试与生产构建冒烟；依据失败修正，不以修改断言掩盖行为退化。

## 必须验证的场景

- 带筛选的图库打开详情、连续换图、关闭、前进/后退；过滤结果之外的直达照片仍可查看。
- 详情尾斜杠、特殊字符 ID、未知 ID、直接访问、刷新、有无 history state。
- 图库→地图→详情→关闭回地图；详情→地图→返回图库；地图查询不污染图库。
- 动画正常完成、减少动态效果、缺失缩略图目标、动画期间新导航，旧回调不能覆盖新页面。
- 地图视角与图库滚动恢复，键盘焦点和修饰键点击保持可用。
- 详情换图不会触发整片图库重渲染；来源序列固定，hydrate 不改变导航顺序。
- 分享链接独立可打开；原图加载的已有生产回归继续通过。

## 实施结果

已接入统一导航控制器，移除 `useGalleryUrlSync`、Router atom 镜像与查看器开关/索引原子。图库筛选直接读取 URL；地图、命令面板、详情标签和分享入口遵守上述规则。图库位置恢复与地图视角恢复已接入；关闭动画通过完成事件提交，并防止旧动画及尚未完成的新路由加载相互覆盖。

回归中另发现并修复了分享复制函数丢失原生 Clipboard 对象上下文的问题。分享 URL 通过真实浏览器剪贴板读取验证，不含筛选与返回来源参数。

本地验收结果：

- 全量单元测试：191 个文件、1,211 项通过。
- 完整 workspace 类型检查、ESLint、Prettier 和 `git diff --check` 通过。
- 真实生产构建与 Chromium：9 项通过，覆盖原图加载、Service Worker、导航往返、滚动恢复、减少动态效果和分享链接。
- 交互回归：10 项通过，覆盖地图视角恢复、命令面板、桌面鼠标和移动触摸关闭；另 4 项按设备条件跳过。

以上生产验收针对本地构建与预览服务，不代表已发布到 Vercel。图片转换队列、缓存预算等其他架构审计项目仍见原审计文档，不包含在此次导航重构中。
